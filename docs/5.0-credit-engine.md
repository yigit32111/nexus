# NEXUS 5.0 — Credit Engine candidate

This is an isolated test-only SQL candidate, not a deployed Supabase migration. No real payment or provider calls are enabled. The planned offer is 399 TL/month with a shared USD 5 credit budget. Monthly periods currently use UTC calendar months, not payment anniversaries.

A server-provisioned wallet is required. An atomic row lock serializes reservations, request UUIDs prevent a second provider call using the same reservation ID, and settlement is idempotent. A verified actual cost replaces the reservation; if actual cost exceeds the reservation it is recorded and the wallet blocks further reservations. Unknown cost stays reserved until trusted reconciliation; never automatically release an uncertain charge. Wallet grants are service-role only. Supabase production migration/advisors, subscription validity and revocation, signed payment events, usage lookup/reconciliation, global cost ceiling, separate premium provider keys and real provider E2E remain prerequisites. This implementation does not guarantee an upstream provider never overcharges.

CI creates synthetic auth rows inside an isolated PostgreSQL 17 service, tests permissions and ownership, invalid amounts, replay, settlement, overage, and 20 concurrent reservations of $0.50 against a $5 wallet. It must accept 10 and refuse 10. It uses no live data, credentials, or paid API.
