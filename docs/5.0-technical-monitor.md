# NEXUS 5.0 — privacy-minimized Sentry event transport

This first phase uses Sentry's documented HTTPS envelope ingestion endpoint, not the full Next.js SDK. Registry access was unavailable in the editing environment; no unverified dependency or lockfile update was introduced. SENTRY_DSN is the only configuration used by runtime. SENTRY_AUTH_TOKEN is not read or transmitted by this implementation; revoke unused tokens when not needed. SENTRY_ORG and SENTRY_PROJECT are unnecessary for ingestion.

Only production server execution reports fixed technical categories: unexpected chat error, timeout (not ordinary cancellation), provider 5xx, usage log write failure, and uncaught Next server errors. There is no browser capture, replay, breadcrumbs, tracing, exception text, stack, request data, user ID, content, IP field, file, cookie or auth token in the event. Sentry may see the server egress IP from the network connection. Configure Sentry project data scrubbing and disable IP storage as additional safeguards. No public test endpoint. No new permissions, paid access or database changes.

Strict official SaaS ingestion host validation, HTTPS, no redirects, 1.5s deadline, per-category 60s cooldown (maximum six events per minute per process), 429 backoff and no retries. Monitoring failures are ignored; it is best-effort, not an audit ledger. Unit tests use fake DSNs and mocked transport only. Real delivery is tested by the authenticated owner using Admin Center → Sentry test olayı gönder. The server action checks getCoreAdmin again, rejects invalid/missing DSN, ignores all submitted data and emits only a fixed MONITOR_TEST event. A successful HTTP response confirms ingestion acceptance, not visibility in the Sentry Issues UI. No deliberate application error is required. The owner checks Issues for NEXUS MONITOR_TEST. Full SDK, source maps, client errors and performance monitoring are not part of this change.

Protocol reference: https://www.sentry.help/en/articles/13964242-can-i-send-errors-to-sentry-without-using-an-sdk
